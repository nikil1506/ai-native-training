**L12** A multi-agent pipeline versus one agent*[Track B · Building agentic systems]*  (Day 11 · 3 h)

**Objective.** Build a small team of agents with an independent reviewer, and check whether it really beats a single agent.

**Starter.** `starter/incidents` — three incident bundles with planted mistakes, an orchestrator skeleton with two researcher agents already wired in, JSON schema files, and a scoring rubric.

**Guided start.** The facilitator runs the skeleton end to end and points out where the hand-offs happen.

##### Tasks

1. Baseline: let one agent write a postmortem for each incident and score it with the rubric.
2. Add a writer agent and an independent reviewer agent (new context) to the skeleton. The reviewer checks claims against the sources.
3. Make every hand-off follow the provided JSON schemas and check them in code.
4. Compare with the baseline on accuracy, completeness, cost and time.
5. Write a few sentences on when the team was and was not worth the extra cost.

##### Hint cards

- Give the reviewer the sources and the draft, but not the writer's reasoning.
- If a hand-off fails validation, print the message and the schema side by side.
- Put a limit on review rounds.

##### Deliverables

- Your system code
- `comparison.md`

##### Acceptance criteria (tick as you go; saved in this browser)

- [ ] All hand-offs are checked against a schema
- [ ] The reviewer catches at least one planted mistake
- [ ] The comparison covers quality, cost and time
- [ ] Your conclusion is backed by the numbers

##### Stretch

- Add a second review round, with a limit of two.

##### Common pitfalls

- Agents sharing one context
- Hand-offs in free text
- Review loops with no limit
