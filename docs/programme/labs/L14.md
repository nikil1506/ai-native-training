**L14** Attack an agent, then harden it*[Cross-cutting · Security & governance]*  (Day 13 · 3 h)

**Objective.** Think like an attacker for a while, then fix what you find.

**Starter.** `starter/vulnerable-agent` — an assistant with email, file and web tools plus RAG, with deliberate weaknesses, and five ready-made attack documents.

**Guided start.** The facilitator runs one injection attack live and shows what the agent does with it.

##### Tasks

1. Write a short threat model: what the agent can touch, how data gets in, what you do not trust.
2. Try three of the five attack documents and record what happened.
3. Harden the agent: give each tool only the access it needs, allow only approved web addresses, ask for approval before sensitive actions, treat document text as data not instructions.
4. Run the same attacks again and show they now fail, or note what risk remains.
5. Add a log of every tool call.

##### Hint cards

- Ask: what is the worst thing this tool could do if the model were tricked?
- Telling the model "don't" is not enough; remove the ability.
- Never put secrets into the prompt.

##### Deliverables

- `threat-model.md`
- Attack notes
- Hardened code
- Sample tool-call log

##### Acceptance criteria (tick as you go; saved in this browser)

- [ ] Three attacks worked before hardening and are recorded
- [ ] The same attacks fail afterwards, or the remaining risk is written down
- [ ] Sensitive actions need approval
- [ ] Secrets never appear in prompts or logs

##### Stretch

- Add your attacks to your eval as test cases.

##### Common pitfalls

- Relying only on instructions to the model
- Securing the prompt but not the tools
