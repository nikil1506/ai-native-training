**L7** Design tools for an agent, and wrap them in MCP*[Track B · Building agentic systems]*  (Day 6 · 3 h)

**Objective.** Design a small set of tools an agent can use well, and see how much the descriptions matter.

**Starter.** `starter/orders-api` — a mock REST API with six endpoints (one destructive), an MCP server template, and eight task prompts.

**Guided start.** The facilitator turns one endpoint into a tool live and shows how a good description changes the agent's choice.

##### Tasks

1. Choose at most four tools. Write each name, description and parameters. Decide which endpoint to hide or guard, and write why.
2. Implement them as function-calling tools, then expose them with the MCP server template.
3. Connect an agent and run the eight task prompts.
4. Make the descriptions worse on purpose (vague names, overlapping tools), run again, and note the difference.
5. Make errors helpful: return a clear message and a hint about what to try next.

##### Hint cards

- Describe a tool the way you would explain it to a new colleague.
- A tool that deletes something should ask for explicit confirmation or not exist.
- Keep tool outputs short; long outputs confuse the agent.

##### Deliverables

- Your tool code and MCP server
- `tool-design.md`
- Before/after table

##### Acceptance criteria (tick as you go; saved in this browser)

- [ ] The destructive action needs confirmation, or is left out with a reason
- [ ] At least five of eight tasks succeed
- [ ] The before/after table shows a difference and you explain it
- [ ] Errors include a hint

##### Stretch

- Add an MCP resource or a prompt template.

##### Common pitfalls

- One tool per endpoint without thinking
- Tools that overlap
- Very long outputs
